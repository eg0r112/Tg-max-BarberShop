# Акварель — запись и QR-оплата в Telegram и MAX

Онлайн-запись в парикмахерскую **«Акварель»** и выставление счёта по QR прямо в чат клиенту.
Один Python-бэкенд, одно мини-приложение, два бота (Telegram и MAX).

## Как это работает для людей

### Клиент
1. В боте нажимает **«Записаться»** (или кнопку меню рядом с полем ввода).
2. **Услуга → мастер (или «любой») → дата и время → имя и телефон** → готово.
   Имя и телефон запоминаются для следующего раза.
3. В чат приходит подтверждение, затем напоминания за сутки и за 2 часа.
4. В разделе **«Мои записи»** можно перенести или отменить визит (с подтверждением) — не позднее чем за 2 часа (`CANCEL_MIN_HOURS`). Позже — только по телефону.
5. После услуги мастер выставляет счёт — клиент получает QR-код в чат.

### Мастер / администратор
Открывает бота → **«Открыть кабинет»**. Клиентских кнопок в кабинете нет.

- **Записи** — день за днём, фильтр по мастеру, перерывы и выходные видны прямо в ленте.
  У каждой записи: «Выставить счёт» (сумма по прайсу, можно изменить) → подтверждение → QR уходит клиенту,
  а на экране мастера показывается тот же QR (если клиент рядом). Потом «Клиент оплатил».
  В меню «⋯»: позвонить, перенести (на другое время или к другому мастеру — клиент получит уведомление),
  отметить «состоялась / не пришёл», удалить запись.
- **График** — у каждого мастера свой: перерыв на время, выходной на день, недельный график.
  Если на это время уже есть записи — приложение предупредит и спросит подтверждение.

Любое удаление, отмена, перенос и выставление счёта требуют подтверждения.

## Запуск

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt
copy .env.example .env          # заполните .env (см. ниже)
python -m app.main
```

Мини-приложение: http://127.0.0.1:8000/app/

Локальная проверка без Telegram/MAX (только при `DEV_MODE=true`):
- клиент: `/app/` (или `/app/?uid=1002&name=Анна`)
- мастер: `/app/?staff=1` (пользователь `9001`, он должен быть в `STAFF_TELEGRAM_IDS`)

Для реальной работы нужен **HTTPS** (VPS, `cloudflared tunnel --url http://127.0.0.1:8000` и т. п.).
Укажите `PUBLIC_BASE_URL`, `TELEGRAM_WEBAPP_URL`, `MAX_WEBAPP_URL` (`https://…/app/`) и токены ботов.
Кнопка меню в Telegram ставится ботом автоматически.

## Настройки `.env`

| Параметр | Зачем |
|---|---|
| `SHOP_PHONE`, `SHOP_ADDRESS` | показываются клиентам, кнопка «Позвонить» |
| `STAFF_TELEGRAM_IDS`, `STAFF_MAX_IDS` | кто видит кабинет мастера (через запятую). `ADMIN_*` — то же, роль admin |
| `PAY_NAME`, `PAY_PERSONAL_ACC`, `PAY_BANK_NAME`, `PAY_BIC`, `PAY_CORRESP_ACC`, `PAY_INN` | **реальные реквизиты салона** для QR (ГОСТ Р 56042). Без них счета не выставляются |
| `WORKDAY_START/END`, `SLOT_MINUTES` | рабочее время по умолчанию и шаг слотов |
| `CANCEL_MIN_HOURS`, `MIN_LEAD_MINUTES`, `BOOKING_HORIZON_DAYS`, `MAX_ACTIVE_BOOKINGS` | правила записи |
| `REMINDERS_ENABLED` | напоминания клиентам |
| `SECRET_KEY` | ключ подписи сессий (если пусто — создаётся `data/secret.key`) |
| `DEV_MODE` | **в продакшене должно быть `false`** |

## Надёжность

- Двойная запись невозможна: одна и та же логика считает свободные окна и проверяет запись, плюс блокировка от гонок.
- Клиент не может записаться на пересекающееся время к разным мастерам; есть лимит активных записей.
- Роли берутся только из `.env` на каждом запросе; подлинность пользователя проверяется подписью `initData` Telegram/MAX.
- Сбой отправки уведомления не ломает запись; если QR не удалось отправить в чат, мастер видит это и показывает QR с экрана.
- Все имена в интерфейсе и уведомлениях экранируются; интерфейс сам восстанавливает сессию и повторяет запросы при обрыве связи.
- Правки цен/услуг/мастеров в базе не затираются при перезапуске.
